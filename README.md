# 轨迹 function 逻辑接入 OCC 显示后的问题记录

本文只记录 `function/` 底层轨迹点生成逻辑接入 `main.py` OCC 显示层后暴露的问题。重点是现象、分析过程、诊断方式和当前解决方案。

## 总体背景

- 前端显示层已经从 matplotlib / PyVista 改为 pythonocc-core 的 OCC/Qt 显示。
- 轨迹点生成仍由 `function/` 内的原始数学逻辑负责。
- OCC 只负责显示点、连线、起点/终点和形状，不参与轨迹规划。
- 因为 OCC 会直接显示点序连接关系，一些原来在 MATLAB 图中不明显的问题会被放大，例如裁剪后的跨段连线、球面边界采样不均匀等。

## 1. 柱面螺旋线出现交叉线和尖刺

### 现象

柱面螺旋线轨迹显示到投影区域边界或底部时，会出现斜穿过去的长线、交叉线，局部还有尖刺感。看起来像某些线上少了一些点，导致前后点被错误连起来。

### 分析

`function/traj_cylindrical.py` 的柱面螺旋逻辑是：

1. 先生成完整阿基米德螺旋线。
2. 再按矩形/圆形投影区域裁剪点。
3. 裁剪后，中间被删除的无效点不再存在。

这样会导致“过滤后列表里的相邻点”不一定是原始螺旋曲线上的连续相邻点。如果显示层直接把过滤后的前后点连线，就会跨过被裁剪掉的区域，形成交叉线和尖刺。

### 诊断

对柱面螺旋点计算相邻点 3D 距离，发现大部分点间距接近 `arc_step`，但有一些距离突然变得非常大。

示例诊断结果：

```text
points 50024
median 1.022
p95 1.325
limit 5.111
breaks 132
max 986.14
```

其中 `max 986.14` 说明有些过滤后相邻点实际跨了很远距离，这些线不应该显示为连续加工路径。

### 解决

显示层增加“长距离断线”逻辑，只对螺旋线启用：

- 位置：`main.py` 的 `_trajectory_shapes`
- 判断：`_should_break_long_edges(params)`
- 逻辑：如果相邻显示点距离明显超过正常点距，就跳过这条边，不画连线。

同时修正柱面螺旋底层边界缩小问题：

- 位置：`function/traj_cylindrical.py`
- 原问题：Python 版额外用了 `edge_margin = arc_step * 0.5`，比 MATLAB 原始逻辑少保留半步边界点。
- 当前处理：删除这个额外边界收缩，按真实投影区域裁剪。

## 2. 球面栅形底部出现大圆弧/空洞

### 现象

球面栅形轨迹在 `R=100, h=100, step=1, line_spacing=2` 这类参数下，底部出现明显圆弧和空置区域。用户预期是步长为 1 时，点应该较均匀覆盖球面，不应该底部空出一大块。

### 初步误判

一开始怀疑是圆形投影边界没有精确落在圆上，于是尝试让每条扫描线端点精确落到投影圆边界。

这个做法会强行增加边界点，但没有解决“底部大面积空置”的本质问题。原因是它只是补了每条扫描线的端点，不会改变球面表面上的真实点距分布。

### 深入诊断

给球面轨迹增加了诊断输出：

- 投影半径 `r_proj`
- 实际 XY 半径范围 `r_xy`
- Z 范围
- 相邻点距离的 median / p95 / max
- 扫描线数量
- 每条扫描线点数范围
- 底部若干扫描线的点数和 Z 范围
- 最大行间跳变距离

旧逻辑诊断结果：

```text
points 15701
rmax 100.0
Z [0.0, 100.0]
相邻点距离 median 1.155
p95 3.167
max 20.0

底部扫描线:
y=-100.0  count=1
y=-98.0   count=39
y=-96.0   count=57

最大行间跳变:
-100.0 -> -98.0  dist=20.0
```

这个诊断说明：

- 投影圆本身没有超界，`rmax=100` 是对的。
- 但球面表面相邻点距离最大达到 `20mm`。
- 底部第一条扫描线只有 1 个点，第二条扫描线突然有 39 个点。

所以问题不是 OCC 显示，也不是简单缺几个边界点，而是球面栅形的底层采样方式错用了“投影平面等间距”。

### 根因

原球面栅形逻辑是：

1. 在 XY 投影平面内按固定步长/行距生成圆形栅格。
2. 再通过 `z = sqrt(R^2 - x^2 - y^2)` 映射到球面。

这会导致靠近球面底部边界时，投影平面上很小的半径变化对应球面表面上很大的弧长变化。也就是说：

- 投影平面里看起来点距合理。
- 映射到球面表面后，底部区域实际点距会突然变大。

因此步长为 1 的设置并没有保证球面表面上的点距为 1。

### 解决

球面栅形改为球面专用采样：

- 行间距按球面大圆弧长计算。
- 行内步长按当前纬线圆弧长计算。
- 再把球面角度参数转换为投影 XY 点，最后用原有球面映射逻辑生成 Z 和法向量。

位置：

- `function/traj_spherical.py`
- 新增 `_generate_spherical_raster`
- `traj_type == "G"` 时调用球面专用栅格，而不是普通 `generate_raster_circle`

修改后同参数诊断：

```text
points 31654
rows 159
count range 1..316
rmax 100.000001
Z [0.0, 99.995738]
相邻点距离 median 1.0
p95 1.0
max 2.0
```

底部扫描线现在逐步展开：

```text
y=-100.000000  count=1
y=-99.980001   count=8
y=-99.920011   count=14
y=-99.820054   count=20
```

这说明球面表面点距已经按用户输入的步长/行距控制，不再出现 20mm 的异常跳变。

## 3. 栅形轨迹和螺旋轨迹的连线规则不能共用

### 现象

为了修柱面螺旋裁剪后的跨段连线，一开始在显示层对所有轨迹都启用了“长距离断线”。这会导致球面栅形底部有点但线不连，看起来像底部断开。

### 分析

栅形轨迹和螺旋轨迹的点序含义不同：

- 螺旋线经过投影区域裁剪后，过滤后的相邻点可能跨越无效区域，长距离连接应该断开。
- 栅形轨迹每一行结束后切换到下一行，行间连接可能比普通步长长，但它是合法的路径连接，不应该被自动断开。

### 诊断

球面栅形诊断显示：

```text
display_break_long_edges=False
```

栅形轨迹不应该启用螺旋线的长距离断线逻辑。

### 解决

显示层改成按轨迹类型判断是否断线：

- 螺旋线：启用长距离断线。
- 栅形线：不启用长距离断线。

位置：

- `main.py`
- `_should_break_long_edges(params)`
- `_trajectory_shapes(..., break_long_edges=...)`

## 4. OCC 显示抽稀造成假连线

### 现象

点数多时，为了避免 OCC 创建过多对象，显示层会抽稀点和线。最早的连线方式是按 `p[i] -> p[i + stride]` 连接，可能造成视觉上跨过中间点的假线。

### 分析

如果抽稀后仍然按原始跨度连接，会让轨迹看起来像某些线缺点或斜穿。正确做法是：

1. 先生成抽稀后的显示点列表。
2. 再连接抽稀列表里的相邻点。

### 解决

当前显示层改为：

```python
line_pts = [points[i] for i in range(0, n_pts, stride_edges)]
for p1, p2 in zip(line_pts, line_pts[1:]):
    edge_shapes.append(self._edge_shape(p1, p2))
```

位置：

- `main.py`
- `_trajectory_shapes`

## 5. 当前诊断输出的作用

球面轨迹生成后，会在右侧结果输出中追加诊断信息。这个输出用于判断问题属于哪一类：

- `r_xy` 是否超过 `r_proj`：判断投影点是否越界。
- `Z` 范围是否符合几何高度：判断球面映射是否正确。
- `path distance median/p95/max`：判断是否存在异常跳变。
- `rows` 和 `row_count`：判断扫描线是否过少或某些行点数异常。
- `sample scan lines`：查看底部/顶部扫描线展开情况。
- `largest row-to-row jumps`：定位最大的行间跳变发生在哪里。

后续如果再出现球面、柱面、锥面显示异常，应优先看诊断输出，不要直接改显示颜色或强行补点。
