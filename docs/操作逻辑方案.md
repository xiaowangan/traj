> 日期：2026-10-26

> 状态：D1–D6 按建议实施（D6 只预留），实施记录见 `docs/改动记录.md` 第三轮。

## 0. 从零出发：用户到底在做什么

用户是抛光工艺人员。他手上有**一块镜子**，要把它从“现在的样子”加工到“图纸要求的样子”，并且尽量少走弯路、留下证据。

把这件事拆到不能再拆，只有六个问题，顺序也是固定的：

| # | 用户心里的问题 | 必须先有什么 | 软件里的阶段 |
|---|---|---|---|
| 1 | 我要做成什么样？现在是什么样？ | 图纸参数、一份测量文件 | 建档 |
| 2 | 差多少？哪里不合格？标准是什么？ | 1 | 评价 |
| 3 | 用什么方法、什么工具、什么参数去做？ | 2（差在哪决定用什么方法） | 规划 |
| 4 | 照这个做，能做到吗？要多久？ | 3 | 预测 |
| 5 | 怎么交给机床？ | 4 并且**我确认了**这个方案 | 执行 |
| 6 | 实际做成什么样？预测准不准？要不要再来一轮？ | 5 + 加工后测量 | 复测 → 验证 → 归档 |

两点基本事实决定了界面该怎么设计：

1. **每一步的输入都是上一步的输出。** 所以界面必须让用户“按顺序走”，前面没做完，后面要明确告诉他“缺什么、去哪补”。
2. **抛光是多轮迭代的。** 第 6 步不达标时，加工后的面形就是下一轮的“加工前面形”。主线是一个环，不是一条直线。

另外有一类东西**不属于某一次加工**：工具库、抛光斑/TIF 标定、设备能力。它们长期维护、反复使用，放在“工艺资源”，主线里只做“选用”。

## 1. 界面七条原则（所有页面通用）

| 编号 | 原则 | 用户感受到的是 |
|---|---|---|
| R1 | **一页一个问题**：页首一句人话说明“这页帮你回答什么” | 知道自己在干什么 |
| R2 | **步骤编号 + 每步一个主按钮**：参数在上，主按钮在下，结果紧跟按钮 | 知道先做哪个、点哪个 |
| R3 | **前置没完成就灰掉，并写明缺什么、给跳转**（软锁：页面能看，按钮不能点） | 不会做无用功，也不会迷路 |
| R4 | **每个参数只在一个地方填**。别处需要时只读显示“来自××”，或干脆不显示 | 不会两处填得不一样 |
| R5 | **状态三种**：未完成 / 已完成 / **已失效（上游改了，需要重做）**，失效要说原因 | 改了前面的参数，知道后面哪些要重算 |
| R6 | **分支只走一条**：规划里选定加工方式后，预测、执行只显示这一种方式的内容，另一种灰掉并说明原因 | 不会点错分支 |
| R7 | **左侧画板 = 当前这一步的结果**；没有结果就说明“做完哪步后这里显示什么” | 左右对得上（上一轮已做） |

## 2. 主线总图

```text
                       工艺资源（长期维护，主线里只“选用”）
                       工具库 · 抛光斑/TIF 标定 · 设备能力
                                 │ 选用
                                 ▼
 ┌─ 建档 ─→ 评价 ─→ 规划 ─→ 预测 ─→【确认方案】─→ 执行 ─→ 复测 ─→ 验证 ─→ 归档
 │                    ▲         │ 不达标                       │ 不达标
 │                    └─────────┘ 回规划改参数                  │
 └──────────────────────────────────────────────────────────────┘
          下一轮：本轮加工后面形 = 下一轮加工前面形
```

新增的唯一一个“关口”是 **【确认方案】**：预测满意后用户点确认，方案冻结，执行才解锁。这是业务文档里早就要求的（“预测先于加工、复测后不得修改预测”），现在界面里没有。

## 3. 每个阶段的操作逻辑

### 3.1 建档：我要做成什么样？现在是什么样？

| 步骤 | 内容 | 完成条件 | 现状差异 |
|---|---|---|---|
| 1 期望曲面 | 口径 → 面形类型及参数 → 离轴量 → 生成曲面模型（计算网格放进“高级”折叠） | 模型已生成 | 基本不变 |
| 2 实测面形 | 选文件 → 裁边/延拓/滤波（可选）→ 看 PV/RMS | 面形已导入 | **第 1 步没完成时灰掉**（导入要用期望曲面的网格重采样，现在不灰，靠报错） |
| 3 对齐检查 | 自动：实测数据和期望曲面对得上吗（覆盖率、中心偏移） | 检查通过或用户确认警告 | **从评价页挪到这里**：它检查的是“数据对不对”，属于建档的收尾 |

总览页保留（三步清单 + 状态）。

### 3.2 评价：差多少？标准是什么？

| 步骤 | 内容 | 完成条件 | 现状差异 |
|---|---|---|---|
| 1 评价标准 | 中频频段、低阶去除、窗函数、高度单位/波长 | — | **去掉“评价当前实测面形”这个先要点开的按钮**，直接显示 |
| 2 加工目标 | 中频 RMS 上限、去低阶 RMS 上限、时间上限 | — | 不变 |
| 3 计算并看结论 | 计算评价结果 → 结论：哪些超差、超多少 | 评价已完成 | **新增一句建议**：“低频面形超差为主 → 建议扫描驻留；中频超差为主 → 建议共形振动”（只是建议，规划里由用户选） |

### 3.3 规划：用什么方法、工具、参数？

先选方法，因为方法决定后面要填什么。“工具与设备”页拆散并入这里（理由见第 4 节）。

**扫描驻留：**

| 步骤 | 内容 | 现状差异 |
|---|---|---|
| 1 加工方式 | 扫描驻留 / 共形振动（显示评价给的建议） | 不变 |
| 2 工具与贴合 | 工具类型、抛光盘口径 → **自动**用期望曲面的 R/K/A 做贴合检查 → 左侧显示间隙曲线；可折叠“工况记录”（抛光阶段、盘材料、转速、压力） | **合并原“工具与设备”页**；R/K/A4…和工件口径不再手填，直接取建档结果 |
| 3 抛光斑/TIF | 显示当前 TIF；没有就“去工艺资源导入/标定”，做完自动回来 | 不变 |
| 4 覆盖路径 | 路径形式、行间距、点间距、走刀方向 → 预览 | 不变；**这里定下的路径就是执行用的路径** |
| 5 生成方案 | 列出缺项；齐了才能点 | 不变 |

**共形振动：** 1 加工方式 → 2 工具与贴合（同上）→ 3 振动参数 → 4 生成方案。

### 3.4 预测：照这个做能做到吗？

页面内容**按规划选定的方式只显示一种**。没生成方案时整页灰掉：“请先在规划中生成方案”。

**扫描驻留：**

| 步骤 | 内容 |
|---|---|
| 1 求解区域 | 轨迹区裁边、评价区裁边 |
| 2 求解方法 | 算法及参数 → **求解驻留时间** |
| 3 边缘修饰（可选） | 修饰宽度、调整量 → 驻留时间修饰 |
| 4 达标判定 | 自动显示：加工前 → 预测后，达标/未达标；“查看前后对比” |
| 5 确认方案 | 达标 → **确认并冻结方案**（解锁执行）；未达标 → “返回规划调整”（也允许强制确认，需说明理由） |

**共形振动：** 1 参数（只读，来自规划，可点“去修改”）→ 2 预测中频演化 → 3 达标判定与达标时间 → 4 确认方案。

预测的“总览”页取消：只剩一种方式，总览只是多一次点击。现在“两张卡片跳到同一页”的问题随之消失。

### 3.5 执行：怎么交给机床？

没有冻结方案时整页灰掉。共形振动方案：显示“共形振动的执行文件尚未支持”，不让用户填一堆用不上的参数。

| 步骤 | 内容 | 现状差异 |
|---|---|---|
| 1 机床设置 | 进给速度上下限、工具球半径、气缸压入量、偏置与姿态、起始点位 | 不变 |
| 2 生成轨迹 | 路径形式、间距、方向**只读显示“来自规划”** → 表面轨迹生成 | **现在这里可以改间距和方向**，改了就和预测用的方案不一致了 |
| 3 生成并保存 CNC | CNC 程序生成 → 保存 | 两个按钮合成一步 |

执行的“总览”页同样取消。

### 3.6 复测 / 验证 / 归档（暂为入口）

- **复测**：导入加工后测量，**自动套用建档时的处理参数和评价标准**（同协议才可比）。
- **验证**：预测后 vs 实测后，对比并判定；不达标 → **“开始下一轮”**：本轮实测面形成为下一轮的加工前面形，回到评价。
- **归档**：冻结整轮或多轮记录。

### 3.7 贯穿全程的两个入口

- **新建案例**：现在没有，只能重启软件。放到“工具”页签，与保存/打开并列。
- **工作路径**：现在藏在“工具与设备”里，实际是保存位置，归到保存案例的对话框里。

## 5. 需要你拍板的决定

| # | 决定 | 我的建议 | 备选 |
|---|---|---|---|
| D1 | “工具与设备”放哪 | **拆散并入规划第 2 步**（工具+贴合自动检查+工况记录）；工作路径归到保存案例 | 保留成规划里的独立标签，但排在“规划方案”**前面** |
| D2 | 预测、执行的总览页 | **取消**，点“预测/执行”直接进对应方式的页面 | 保留总览，按方式点亮一张、灰掉另一张 |
| D3 | 加“确认方案”关口 | **加**，未达标时允许强制确认但要写理由 | 不加，执行随时可做 |
| D4 | 前置未完成时 | **软锁**：能看、不能点，写明缺什么并给跳转 | 硬锁：标签/页面都进不去 |
| D5 | 评价给“建议加工方式” | **加**，只是建议 | 不加 |
| D6 | 多轮迭代（“开始下一轮”） | 先在逻辑上预留，**本次不做**，等复测/验证实现时一起做 | 现在就做 |

确认后按这个顺序改：
D4 软锁与失效提示 → D1 规划合并 → D2/D3 预测与执行 → 评价/建档小调整 → 新建案例。每改完一块都跑全部测试、截图检查，并补改动记录。
